# Anonymous Q&A Forum

Репозиторий содержит исходный PHP-макет и Android-проект на Java в каталоге [`android/`](android/). Android-версия не использует PHP-сервер, MySQL, Redis или внешний сервер форума: вопросы хранятся локально и по возможности реплицируются между пользователями внутри Yggdrasil.

Скачать полный Android Gradle-проект: [`Forum-Android.zip`](Forum-Android.zip). Архив содержит исходники и ARM64-библиотеку; это проект для сборки, не готовый APK.

## Запуск Android-приложения

Откройте `android/` в Android Studio или выполните:

```sh
cd android
./gradlew assembleDebug
```

Нужны JDK 17, Android SDK 35 и Gradle 8.9 (wrapper включён). Минимальная ОС — Android 5.0 / API 21. Предоставленное нативное ядро поддерживает только `arm64-v8a`; на 32-битных ARM и x86 нужен отдельный native build. При недоступном ядре локальная Q&A-функциональность остаётся доступна.

## Модули

- `MainActivity.java` и отдельные `AskScreen`, `FeedScreen`, `DetailScreen`, `SettingsScreen`, `SidebarPanel`, `UiComponents` — модульный UI.
- `ForumCore.java` — локальные вопросы/ответы, квота и кредиты, TTL, дедупликация и очередь исходящих событий.
- `ForumMesh.java` — подписанное app-level presence, локальный TTL-кэш участников, детерминированный выбор реплик и проверка сообщений.
- `ForumIdentity.java` — локальный ключ подписи приложения: Android Keystore используется при доступности, иначе возможен fallback в app-private программное хранилище. Приватный ключ не помещается в NodeInfo, сообщения или архив состояния форума.
- `YggdrasilAdminClient.java` и `YggNodeService.java` — best-effort discovery, прямой transport и репликация поверх Yggdrasil/YggChat.
- `Strings.java` и `app/src/main/assets/lang/` — языки, темы и переводы в JSON.
- `net/yggchat/yggchat/` и `go/` — JNI-совместимые обёртки для предоставленного YggChat APK; `app/src/main/jniLibs/arm64-v8a/libgojni.so` — его нативное ARM64-ядро.

## Обнаружение участников и хранение публикаций

Приложение не обращается к внешнему форумному каталогу. Сетевой адаптер настраивает `AdminListen` на Unix-сокет в приватном каталоге приложения и пытается получить локальный Yggdrasil routing tree через Admin JSON API, затем пакетно запрашивает `getNodeInfo`. Это зависит от наличия Admin listener в нативном ядре. Статическая проверка методов JNI и строк поставленного `libgojni.so` не подтвердила наличие Admin listener; его работа на устройстве не проверена, поэтому discovery может сообщать «недоступно» до использования ядра с поддержкой Admin API. В таком случае локальные вопросы сохраняются, а direct/gossip работает только для адресатов с уже проверенным signed presence. Появление узла в routing tree или в списке транспортных пиров **не** делает его участником форума. В локальный кэш попадает только узел, чей ответ NodeInfo содержит корректно подписанную запись `anonymous-forum`, где ключ и адрес совпадают с конкретным Yggdrasil-запросом. Протокол автоматически обменивает публичные ключи и публичный YggChat contact code; приватные ключи не рассылаются.

Список и `lastSeen` хранятся только локально; запись истекает через шесть часов. «Недавно активен» означает, что этому устройству недавно ответили на NodeInfo-запрос или проверенное прямое сообщение. Это не обещает, что приложение участника сейчас запущено или что он доступен для следующей передачи. UI-список участников, ручное добавление contact code/QR и пользовательский выход из общей группы не добавлены.

Каждый пользователь сохраняет свои данные локально. Если есть проверенные подписанные presence и YggChat-маршрут, публичные вопросы и уведомления о количестве ответов подписываются автором и по возможности отправляются выбранным детерминированно трём недавно наблюдавшимся участникам; получатели сохраняют принятые записи локально и могут переслать их дальше. Без такого кэша запись остаётся локальной/в очереди. Тела приватных ответов передаются только автору вопроса и не включаются в публичную репликацию. Есть дедупликация событий и сообщений, подписи, ограничения размера и сроки хранения. Это best-effort gossip, не консенсус и не гарантия доставки.

Текущая реализация сканирует только узлы, видимые в routing tree конкретного Yggdrasil-узла, и делает это небольшими пакетами. Она может пропустить участников, не представленных в этом дереве; это не полный глобальный DHT и не exhaustive-поиск всех пользователей Yggdrasil. Для самой сети всё равно необходим уже работающий Yggdrasil или хотя бы один доступный транспортный peer. Android может остановить или отложить foreground/background работу, поэтому нельзя обещать точный период поиска, постоянное присутствие или срок доставки. Если Admin API/подписанное присутствие недоступны, приложение сообщает об этом и оставляет публикации локально/в очереди.

## Транспортный bootstrap

`app/src/main/assets/network/bootstrap-nodes.json` содержит пять TLS URI из официального списка Yggdrasil public peers, ревизия `301831252b4dbf11a22ea479f6ac26c0763d39aa` от 2026-11-12. Там указаны узлы в Санкт-Петербурге, Москве, Хельсинки и Нюрнберге. Это сторонние транспортные точки входа, не форумные серверы, каталоги или подтверждённые участники; их доступность не гарантирована. Приложение не загружает список пиров из внешнего сервиса.

## Логика и границы доверия

- Один вопрос бесплатно за UTC-сутки; следующие стоят 1 локальный кредит. Один ответ на вопрос добавляет 1 локальный кредит, повторный ответ на тот же вопрос не засчитывается.
- Вопрос без ответов истекает через 24 часа; ответы и публичные уведомления хранятся локально ограниченное время. Темы и подтемы берутся из `config/topics.php`.
- Кредиты, квота и просмотры локальны, не защищены от сброса или Sybil-идентичностей и не являются распределённым токеном.
- «Анонимно» означает без аккаунта и публичного имени, но не без сетевого псевдонима: Yggdrasil-код нужен для прямой доставки ответа. Не помещайте личные данные в вопросы.
- Параметры `ShardSize`, `Redundancy`, `Fanout`, `VaultMax` и `TTLHours` читаются из настроек нативного ядра. Очистка удаляет только shard-vault ядра, не локальные вопросы и ответы.
- Бинарная лицензия/исходники native core не предоставлены; перед публикацией APK необходимо отдельно подтвердить условия распространения (см. [`android/THIRD_PARTY_NOTICES.md`](android/THIRD_PARTY_NOTICES.md)).
